\chapter{Dataset}
\label{ch:datasets}

This chapter describes the datasets used for training and evaluating the TRNet and MISRGRU architectures.

\paragraph{Origin of the simulated data.}
No new simulations were generated for this thesis. All experiments reuse the
existing synthetic dataset produced in the RESURF paper~\cite{resurf2024}.
The data were generated with the publicly available SOFI simulation
tool\footnote{\url{https://github.com/GrussmayerLab/Sofi_Simulations}} together
with the SOFI package\footnote{\url{https://github.com/GrussmayerLab/sofipackage}};
the simulation methodology is described in detail in~\cite{jelle2024, resurf2024}.

\paragraph{This work's contribution to the dataset.}
\emph{Motion augmentation} of the static simulated sequences was introduced in this thesis 
as a preprocessing step to train and
evaluate the streaming model on its ability to reconstruct moving samples.
The implementation is released as part of the
project codebase.\footnote{Motion-augmentation code:
\url{https://github.com/GrussmayerLab/SOFI-TR-MISR/blob/motion/src/motion_augment.py}.}

\section{Synthetic Data }
\label{sec:synthetic}
Fluorescence microscopy experiments are time-consuming and obtaining
super-resolved ground truth from real images is inherently difficult.
Classical SOFI requires hundreds of raw frames to accumulate reliable cumulant statistics,
meaning that acquiring a single ground-truth SR image takes tens of seconds.
Over that interval, live cells drift and fluorophores
irreversibly bleach, so the "ground truth" computed from the later frames reflects
a different sample state than the one seen in the early frames used as input.

For this reason, a simulation-based dataset was used where conditions such as
blinking speed and background noise could be controlled precisely.
The synthetic dataset provides paired low-resolution (LR)
fluorescence stacks of 100 frames with corresponding high-resolution 
(HR) SOFI targets that is used for training. Additionaly, since all data was simulated 
we have access to the actual structure that is being imaged: Ground Truth (GT), 
which is then used to evaluate the structural correlation with our super-resolved prediction.

\subsection{Simulated Data Conditions}
\label{sec:simulation_conditions}

To build a dataset that generalises across different experimental conditions,
simulations were run under 12 distinct settings formed by the
combination of three blinking-speed regimes and four photon-level fractions \cite{jelle2024}:

\begin{itemize}
  \item \textbf{Blinking speeds}: fast, medium, and slow, corresponding to
        fluorophore on/off-times of approximately 600ms, 1200ms, and 2000ms respectively.
  \item \textbf{Photon levels}: 100\%, 80\%, 60\%, and 40\% of the nominal ion photon count,
        progressively reducing the peak signal intensity.
\end{itemize}

\section{Motion Augmentation}
\label{sec:motion_augment}


The synthetic dataset described above contains no sample motion: every frame in a
sequence depicts the same field of view, with fluorophores at fixed coordinates
emitting stochastic blinks.
This is appropriate for the batch MISRGRU and TRNet models, which output a single
SR image from a fixed set of $N$ frames.
The streaming MISRGRU (Section~\ref{sec:streaming_arch}), however, is designed to
produce a super-resolved image at \emph{every} time step, making it directly
relevant to live-cell imaging where sample motion is common and unavoidable.
In practice, organelles such as vesicles and mitochondria translate across the
field of view at 0.5--5\,\textmu m/s~\cite{tang2013fast}.
A model trained exclusively on static data has no incentive to track these
movements: since the correct answer is always the same single HR reconstruction,
the network can ignore temporal position entirely.
Our experiments~\ref{fig:motion_visual_comparison} confirmed this where trained models produced
ghosting artefacts in which fluorophore contributions from all positions were
summed rather than localised to the current field of view.

Because paired moving ground-truth data cannot be obtained experimentally, all
motion is synthesised from the existing static dataset.
Motion augmentation converts each static training sample into a drifting sequence
by shifting both the LR frames and the corresponding HR target frame-by-frame
along a synthetic trajectory, forcing the streaming model to predict the HR image
at the current field position.
The implementation is released as part of the
project codebase.\footnote{Motion-augmentation code:
\url{https://github.com/GrussmayerLab/SOFI-TR-MISR/blob/motion/src/motion_augment.py}.}

An earlier approach was perturbing microtubule segment angles frame-by-frame
inside the simulation software~\footnote{\url{https://github.com/GrussmayerLab/Sofi_Simulations}}
using an Ornstein--Uhlenbeck process. This would have required refactoring and
re-running the full SOFI simulation pipeline for every trajectory, and was quickly
abandoned for that reason; the motion augmentation described here instead operates
purely on the already-simulated frames.

\subsection{Sinusoidal Drift Trajectory}
\label{sec:trajectory_gen}

Rather than a random walk, which can accumulate arbitrarily large displacements,
the trajectory is modelled as an independent sinusoid on each spatial axis:
%
\begin{equation}
  \tau_a(t) = A_a \sin\!\left(2\pi f_a\,t + \varphi_a\right), \qquad a \in \{y,\,x\}.
  \label{eq:sinusoid}
\end{equation}
%
The normalised frequency is $f_a = n_a / T$, where
$n_a \sim \mathrm{Uniform}(1.5,\,3.5)$ is the number of oscillation cycles over the
100-frame sequence, and $\varphi_a \sim \mathrm{Uniform}(0,\,2\pi)$ is a random phase
that breaks any correlation between axes.
The amplitude $A_a$ is derived from a user-specified peak velocity $v$
(in LR pixels per frame): since the instantaneous peak velocity of a sinusoid is
$2\pi f_a A_a$, setting
%
\begin{equation}
  A_a = \min\!\left(\frac{v}{2\pi f_a},\;d_{\max}\right)
  \label{eq:amplitude}
\end{equation}
%
guarantees that the maximum drift speed equals exactly $v$, with $d_{\max}$ as a
hard bound that prevents large zero-padded border regions.
This parameterisation decouples biological realism, controlled by $v$, from
trajectory shape, controlled by $n_a$ and $\varphi_a$.
The sinusoidal model also naturally captures the direction reversals that
are characteristic of organelle motion constrained by cytoskeletal tracks.

\subsection{Frame Shifting and Per-Frame Targets}
\label{sec:frame_shifting}

Given a trajectory $\boldsymbol{\tau}$, each LR frame at time $t$ is shifted by
$(dy_t, dx_t) = \boldsymbol{\tau}[t]$ using bilinear interpolation with zero-padding.
The corresponding HR target is shifted by the same displacement scaled by the
upsampling ratio, consistent with the
$2n-7$ output size.

The critical consequence is that each frame $t$ receives its own HR ground-truth
$\hat{\mathbf{y}}_t$.
In the static case, a single HR image is broadcast across all time steps, so the
model can ignore temporal position entirely.
With motion augmentation, the loss $\mathcal{L}(\hat{Y}_t,\,\hat{\mathbf{y}}_t)$
forces the streaming model to predict the HR image at the \emph{current} position
of the field of view rather than a single static image reconstruction.

\subsection{Relevance to Physical Speed}
\label{sec:speed_calibration}

The peak velocity $v$ in LR pixels per frame maps to a physical drift speed via
%
\begin{equation}
  v_\text{real}\;[\mu\text{m/s}]
    \;=\; v\;[\text{px/frame}]
    \;\times\; r\;[\text{frame/s}]
    \;\times\; p\;[\mu\text{m/px}],
  \label{eq:speed_calibration}
\end{equation}
%
where $r = 100$\,Hz is the camera acquisition rate and $p = 0.1$\,\textmu m/px
(100\,nm per pixel, consistent with the simulated dataset described in
Section~\ref{sec:synthetic}).
The configured speed range $[v_{\min},\,v_{\max}] = [0.2,\,1.5]$\,LR\,px/frame
therefore spans $2 - 15 \text{\textmu m/s}$
%
% \begin{align*}
%   v_{\min} &= 0.2 \times 100 \times 0.1 = 2.0\; \text{\textmu m/s}, \\
%   v_{\max} &= 1.5 \times 100 \times 0.1 = 15.0\;  \text{\textmu m/s}.
% \end{align*}
%
The biologically relevant range for vesicle and mitochondria drift is
0.5--5\,\textmu m/s~\cite{tang2013fast}, with fast kinesin-driven transport
reaching up to approximately 7.5\,\textmu m/s.
The upper bound of 15\,\textmu m/s therefore exceeds the typical biological speeds.
This way we can stress-tests the model during training: by exposing
the network to displacements larger than those encountered in practice, we encourage
it to learn more robust motion-aware representations, with the expectation that
generalisation to in-distribution speeds will be stronger as a result.

Both bounds are exposed as configuration parameters (\texttt{speed\_min},
\texttt{speed\_max}), making it straightforward to restrict training to slow
or faster motion.

\subsection{Integration into Training}
\label{sec:motion_training_integration}

Motion augmentation is applied on-the-fly inside the
\texttt{StreamingTensorDataset} data loader.
For each training sample, a motion augmentation is applied with a probability of $p_\text{motion} = 0.7$
This way model remembers to reconstruct static samples as well.
When augmentation is applied, peak velocity is drawn uniformly from $[0.2,\,1.5]$\,LR\,px/frame,
a trajectory is generated, and the frames and
targets are shifted accordingly with $d_{\max} = 38$\,LR\,px.
Otherwise the static HR image is kept across all $T$ frames.
